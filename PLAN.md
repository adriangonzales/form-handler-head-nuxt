# form-handler-head-nuxt — Project Plan

Nuxt frontend (dashboard) for the **Headless Form Handler** API (`../form-handler-headless-laravel`).
API spec: `http://127.0.0.1:8001/docs/api.json` (OpenAPI 3.1, generated by Scramble). Base URL: `http://127.0.0.1:8001/api`.

Detailed requirements for each area (functional requirements, acceptance criteria, API dependencies, gaps) are in [`docs/prds/`](docs/prds/README.md). This plan stays the overview of the architecture and milestones; the PRDs are the reference to build and test against.

## 1. What the API gives us

| Area | Endpoints | Notes |
|---|---|---|
| Auth | `POST /v1/auth/login`, `/refresh`, `/logout`, `GET /v1/auth/me` | JWT bearer. TTL 60 min. Refresh window 7 days (`JWT_REFRESH_TTL=10080`). Refresh blacklists the old token. **No sign-up endpoint** — accounts are created with `php artisan user:create`. |
| Password reset | `POST /v1/auth/forgot-password`, `/reset-password` | Reset email links to `PASSWORD_RESET_URL?token=…&email=…`, default `http://localhost:3000/reset-password` — this app's dev URL. |
| Account | `PATCH /v1/auth/me`, `PUT /v1/auth/password`, `DELETE /v1/auth/me?password=` | Changing the password revokes all tokens and returns a new one, so the session has to be updated. |
| Forms | CRUD under `/v1/forms`, plus `restore` and `duplicate` | Paginated: 15 per page by default, `per_page` 1–100. `sort` = created_at/updated_at/name (± for direction), `filter[active]`. **List items only** include `entries_count` and `unread_entries_count` (both excluding spam and deleted entries) and `spam_entries_count`; a single form's response doesn't. `schema` is an object keyed by field ID: `{label?, name?, rules?}`. `name` is the input name and defaults to the ID. `rules` are Laravel validation rules, as an array or a comma-separated string. `settings` keys are all optional and nullable, and default when left out; unknown keys are rejected. They are `redirect`, `timezone`, `domains` (string[]), `message`, `honeypot_enabled` (bool) and `honeypot_name`. |
| Entries | `GET/POST /v1/forms/{form}/entries`, `/v1/entries/{id}` (show/update/delete/restore/force) | Paginated: 15 per page by default, `per_page` 1–100. Filters: read, starred, spam, created_from/to, trashed (with/only). Sort by created_at (oldest first by default) or spam_score. `spam_score` is now a 0–1 spam probability from the classifier (see Public submit). `spam_checked_at` is when the spam check finished: null while it's queued, or if it couldn't run. |
| Bulk | `POST /v1/forms/{form}/entries/bulk` | Up to 100 ids. Actions: `mark_read, mark_unread, star, unstar, mark_spam, mark_not_spam, delete` (live entries), `restore, force_delete` (trashed entries only). |
| Exports | `POST /v1/forms/{form}/entries/exports`, `GET /v1/entry-exports` (index), `GET /v1/entry-exports/{id}`, `/download` | Queued CSV export: create it, poll its status, then download. The index lists the user's exports across all forms, newest first (`per_page` 1–100), leaving out expired exports and those of deleted forms. It has no form filter. Takes the entry filters and sort; `per_page` is ignored. Download returns 409 if not ready and 410 if expired. `download_url` is a temporary signed link (`EXPORT_DOWNLOAD_URL_TTL`, default 5 min) that needs no bearer token, and is `null` until the export completes. `/download` returns 403 for a missing, altered or expired signature. The signature is relative (`signed:relative`), but the URL is absolute and uses the host Laravel saw on the request that fetched the export. |
| Notifications | CRUD under `/v1/forms/{form}/notifications`, `/v1/notifications/{id}` + restore | Types: `email` or `sms`, with a `value` and `enabled`. `error` shows delivery problems such as Postmark bounces. |
| Public submit | `POST /v1/forms/{form}/submissions` (no auth) | Body fields are the schema's input names (each field's `name`, or its ID), validated with that field's rules. Unknown fields are dropped. Returns `{redirect, message}` and never a 3XX. Used for the embed snippet and the test-submit tool. After storing the entry, the API runs a queued **AI spam check** (Jev): a likelihood of 0.9 or more flags the entry as spam. Alerts are sent only after the check, and never for spam. Without a classifier key, or if the call fails, the entry is left unflagged. User-agent parsing, the spam check and alerts apply to public submissions only. |

Errors follow Laravel's shapes: 422 `{message, errors: {field: [..]}}`, 401, 403, 404.

### Spec accuracy (re-checked 2026-10-01, after the backend changes)
The generated types can be used as they are. All of these are now correct in the spec:
- form `schema` and `settings`, including the `FormResource.settings` response shape;
- the bulk `action` enum;
- boolean fields on entry and notification updates;
- optional entry filters (`FormEntryIndexRequest`);
- `input` and `user_agent_display` documented as objects, rejected if sent;
- the public submission body contract;
- the signed `download_url`;
- `per_page` on the forms and entries lists, and the optional entry counts on `FormResource` (`FormListItem` in `models.ts` makes them required for list rows).

One small gap remains. `FormEntryExportResource.parameters` is typed `string`, but the API returns an object (the filters and sort used). The UI reads it to summarise exports and retry failed ones, so `models.ts` overrides it as `Pick<FormEntryQuery, 'filter' | 'sort'>`.

## 2. Stack

| Concern | Choice | Why |
|---|---|---|
| Framework | **Nuxt 4** (TypeScript strict, `app/` dir) | Current major |
| UI | **Nuxt UI v4** (Tailwind v4, Reka UI) | Gives us tables, forms, modals and toasts out of the box. Good fit for a CRUD dashboard |

| Dates | `@internationalized/date` (comes with Nuxt UI) or `date-fns` | Entry date filters and timezone display |
| Testing | **Vitest** + `@nuxt/test-utils`, **Playwright** for e2e | Unit tests for composables and server utils; e2e against a seeded Laravel |
| Lint/format | `@nuxt/eslint`, Prettier | |
| Package manager | pnpm 10 (pinned in `packageManager`) | pnpm 8 fails on Node 22 (`ERR_INVALID_THIS`) |
| TypeScript | **5.x** (pinned `^5`) | TypeScript 7 (the native port) has no JS compiler API, which `openapi-typescript` and `vue-tsc` need. Revisit when they support it |

## 3. Architecture

```
Browser ──(cookie)──▶ Nuxt/Nitro server ──(Bearer JWT)──▶ Laravel API :8001/api
                       • server/api/auth/*   login/logout/refresh/me/password
                       • server/api/v1/[...] generic authenticated proxy
```

The API is also reachable directly from users' browsers (decided). The browser uses it only for public submissions and signed export downloads; everything authenticated goes through the proxy.

- **Login:** `server/api/auth/login.post.ts` calls Laravel `/v1/auth/login`, then `/v1/auth/me`. It stores `{ user, token, expiresAt, refreshableUntil }` with `setUserSession` (sealed, httpOnly).
- **Session lifetime:** the session cookie's `maxAge` is the JWT refresh window, `NUXT_SESSION_MAX_AGE` = 7 days (604800 s), so it never outlives a token that can still be refreshed.
  - `refreshableUntil` is set from the first login token's issue time plus the window. Refresh keeps the original issue time, so the window doesn't slide.
  - When the window ends, the proxy clears the session without calling Laravel and returns 401. The user logs in again.
  - Keep the value in sync with the backend's `JWT_REFRESH_TTL`.
- **Proxy:** `server/api/v1/[...path].ts` reads the session and injects `Authorization: Bearer`. It forwards method, query and body with `proxyRequest`, or `$fetch` with retry.
  - If `expiresAt` is less than about 2 minutes away, it calls `/v1/auth/refresh` first and saves the new token.
  - On a 401 it refreshes once and retries. If that fails too, it clears the session and returns 401. The client plugin then redirects to `/login`.
  - A per-session lock (an in-memory promise map keyed by session id) stops parallel requests from double-refreshing, since refresh blacklists the old token.
- **Password change:** the proxy for `PUT /v1/auth/password` saves the new token that comes back. Otherwise the user would be logged out right away.
- **Export download:** the UI links straight to the signed `download_url` from the proxied export response. There's no Nuxt download route, and the CSV never streams through Nitro. A signature expires after about 5 minutes, so the UI re-fetches the export just before the user clicks, and again on a 403.
  - **The link has to point at the public API host.** `download_url` uses the host Laravel saw on the request that fetched the export, and that request comes from the Nuxt server. So the proxy must call Laravel through its public URL (`NUXT_API_BASE` = the public API origin). If it calls an internal address in production instead, it must send `X-Forwarded-Host`/`-Proto`, which Laravel trusts (`config/trustedproxy.php`).
- **Public submission:** the test-submit tool calls the public endpoint straight from the browser (no auth), the same way a real site would. Laravel's default CORS (`api/*`, any origin) allows this.
- **Config:** `runtimeConfig.apiBase` (`NUXT_API_BASE=http://127.0.0.1:8001/api`), `NUXT_SESSION_PASSWORD`, and `NUXT_SESSION_MAX_AGE=604800`. `runtimeConfig.public.apiPublicBase` is the base for embed snippets.
- **SSR:** turned on. Authenticated pages render on the server with the session cookie. The `auth` route middleware (`app/middleware/auth.global.ts`) sends anyone without a session to `/login`, except on the public auth pages.

## 5. Pages and features

| Route | Purpose |
|---|---|
| `/login` | Email and password. Shows the 422 message. Links to forgot password. No sign-up, since the API has none; a note says accounts are created by an admin |
| `/forgot-password` | Always shows the same "check your inbox" message, matching the API's anti-enumeration behaviour |
| `/reset-password?token&email` | New password and confirmation, then redirect to login |
| `/` → `/forms` | |
| `/forms` | Paginated table: name, active badge, entries / unread / spam counts (each linking to that Entries tab), updated date. Page size 15/25/50/100. Sort, active filter and page size are stored in the URL. Row actions: open, duplicate, deactivate/activate, delete (with an undo toast that calls `restore`) |
| `/forms/new` | Name and settings. Can also start from a schema template (contact, newsletter) |
| `/exports` | All recent exports across forms (from the export index): form name, filter summary, status, rows, expiry, Download / Try again. Linked from the sidebar |
| `/forms/[id]` | Tabs: **Entries** (default) · **Fields** · **Settings** · **Notifications** · **Integrate** |
| `/forms/[id]/entries` | Table of entry input values, with columns built from the schema plus any extra keys. Tabs: Inbox/Unread/Starred/Spam/Trash, with count badges on Inbox, Unread and Spam, plus a date range. Spam-likelihood sort. Page size 15/25/50/100; at 100, "select all" matches the bulk limit. Multi-select bulk bar for the actions in §1. Shows trash view actions (restore/force delete) when `trashed=only`. **Export CSV** button, plus an **Exports** popover listing this form's recent exports (the index filtered client-side by `form_id`). Exports in progress are polled every 2 s with backoff. Download re-fetches the export for a fresh signed `download_url`. Handles 403 (expired signature), 409 and 410. Spam-check state per row: Checking… (`spam_checked_at` null, under 2 min old) or Not checked (null, older); the list auto-refreshes while rows are Checking |
| `/forms/[id]/entries/[entryId]` (or a slide-over) | Full input, IP and location, user agent, referer, spam likelihood (as a percentage), reason and check time. An entry can move to Spam shortly after arriving, when the classifier finishes; the view polls while the check is pending. Opening it marks the entry as read. Star, spam/not-spam and delete toggles. Prev/next navigation |
| `/forms/[id]/fields` | **Schema builder:** ordered rows of field ID, label, an optional input `name` (shows the ID as a placeholder, since that's the default) and rules. Rules editor with presets (required, email, max:N, numeric, url, in:a,b) plus free text. Rules are always saved as an array, though either an array or a comma-separated string is read back. Rows can be reordered with drag and drop. Serialises to the `schema` object. Field order relies on JSON key order, so check that the backend keeps it |
| `/forms/[id]/settings` | Name, active, redirect URL, success message, timezone (searchable list from `Intl.supportedValuesOf('timeZone')`), allowed domains (tag input → `string[]`), honeypot toggle and name (a blank name lets the backend generate one). Sends only the keys that changed or were set; unknown keys are rejected |
| `/forms/[id]/notifications` | List of email/SMS recipients with enabled toggle, delivery `error` badge (bounces), add/edit/delete/restore |
| `/forms/[id]/integrate` | Copyable endpoint URL, HTML `<form>` snippet that uses each field's input `name` (or its ID) and includes the honeypot input when enabled, fetch/JS snippet, and a **Test submit** form generated from the schema. It posts to the public endpoint, shows the `{redirect, message}` reply, and maps 422s onto the fields. Notes that fields not in the schema are dropped |
| `/account` | Profile (name, email, with a warning that changing the email removes verification) · change password · danger zone: delete account (needs password, then logs out) |

Cross-cutting features:
- Toasts on every mutation.
- A shared confirm modal for anything destructive.
- 403/404 error pages from `error.vue`.
- Loading skeletons.
- Dark mode, from Nuxt UI's colour mode.
- 422 errors mapped onto `UForm` fields by `utils/apiErrors.ts`.

   - **Tests:** 119 unit tests and 50 Playwright tests (4 for the account: name in the header, a taken email, password change keeping this session and signing out a second browser, and deletion with the wrong and then the right password). **They create throwaway users** with `php artisan user:create` in `E2E_API_DIR` (default `../form-handler-headless-laravel`), and delete them afterwards.
   - **Known edge:** a request already in flight with the old token while the password changes gets a 401, and its refresh fails because the API revoked that token chain, so that tab is signed out. Rare, since the account page is the only thing making requests at that moment.
9. **Polish and tests.** Empty and error states, accessibility pass, Playwright happy paths for each milestone, and a README.

## 7. Testing approach
- **Unit (Vitest):** generated-type guards (`tests/unit/models.test.ts`), token refresh and lock logic, session expiry at `refreshableUntil`, 422 error mapping, schema builder serialisation (array/string rules round-trip, `name` defaulting to the ID), `useListQuery` URL sync, export polling state machine.
- **E2E (Playwright):** run against a local Laravel on :8001, with its queue worker running (exports, spam checks and user agent parsing are queued), and a seeded user (`php artisan user:create`, or a test seeder plus `migrate:fresh --seed` before the suite). Flows: login, create form, test submit, entry shows up (Checking…, then checked) and the form's unread count goes up, bulk star, export download (including a stale signature getting re-fetched, and the export listed on `/exports` after a reload), logout.
- **CI:** typecheck, lint, unit tests. E2E is optional and runs in a job that boots the PHP API.
